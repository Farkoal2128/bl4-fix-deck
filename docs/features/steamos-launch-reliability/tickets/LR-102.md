# LR-102 — Compose existing Steam launch options

Tier: seam

Read: PLAN decisions 2–4; `installer/steamos.py:25`; `dev/steamos_test.py`; PLAN external examples. Depends on LR-101's settled backend tree.

Goal: implement pure `compose_launch_options(existing: str) -> str` in existing `steamos.py`, retaining `LAUNCH_OPTIONS` as the empty-input default. No command execution or Steam/Decky writes.

Files: `installer/steamos.py`, `dev/steamos_test.py`. Limit: <=300 production lines, one production file. No dependency or generic shell grammar.

Accept:
- Enforce the bounded grammar/refusals in PLAN; preserve unrelated raw spans including quotes, spaces, `~/lsfg`, wrapper arguments, game arguments and non-owned environment assignments. Only BL4-owned additions/edits may differ. Empty input returns `LAUNCH_OPTIONS`; whitespace-only input counts as empty.
- Support primary example forms `LSFG_PROCESS=decky-lsfg-vk %command%` and `~/lsfg %command%`, plus a quoted absolute wrapper path containing spaces. Leading `WINEDLLOVERRIDES="dxgi=n,b;dsound=b;version=n"` becomes the same entries/order with only dsound changed to `n,b`. Add dsound when absent; preserve a valid existing override exactly when already correct.
- Exactly one standalone unquoted `%command%`, one leading BL4 flag, one leading Wine override and one standalone exact `-pf_tricks=vcrun2022` argument after `%command%` in generated output. Reject any `-pf_tricks` token before the placeholder, including a wrapper argument; never count or move it. Re-composition is byte-identical; an already-correct complete line is byte-identical.
- Refuse malformed/duplicate/conflicting owned settings and runtime tricks rather than silently replacing unrelated requirements; grouped DLL names containing dsound are unsupported. Reject BL4-owned variable assignments after a wrapper, `env` command wrappers, quoted/embedded/duplicate placeholders, operators/redirection/substitution/expansion and control characters. Only literal quoted override separators are allowed; do not confuse those with shell `;`.
- Error messages identify the unsupported/conflicting item and instruct manual merge while preserving original input. No guessed wrapper environment-forwarding guarantee; callers display that uncertainty.

Tests: `test_launch_empty_and_idempotent`; `test_launch_lsfg_environment_and_wrapper`; `test_launch_preserves_quotes_spacing_and_args`; `test_launch_merges_dll_overrides`; `test_launch_owned_conflicts`; `test_launch_rejects_unsupported_shell`; `test_launch_rejects_runtime_trick_before_placeholder` (including `~/lsfg -pf_tricks=vcrun2022 %command%`, with no counting/moving of the wrapper argument). Table cases include single/double quotes, tilde, unrelated env, dsound-only/absent/already-correct/mixed-case or malformed DLL identifiers, repeated/conflicting settings, `-pf_tricks` other values, NUL/newline, escaped whitespace, unmatched quotes, `$()`, backticks, `$VAR`, pipes, `&&`, redirects and `env -i`. Explicitly choose rejection for syntax outside grammar. Mock subprocess entry points to fail if called and assert fixtures untouched.

Verify: `python dev/steamos_test.py` (focused installer suite); candidate-tree focused receipt. Final full matrix is G-T. Validate spans/semantics in independent review; token presence alone is insufficient.

Stop if: actual owner text needs unsupported grammar (keep safe fallback and report it; no automatic parser expansion), resolving a conflict would delete another DLL override/runtime trick, or the production line bound is exceeded.
